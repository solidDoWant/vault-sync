#462 (found in review of #456) has no committed seed: the simulation's schedules do not reach two devices renaming one note onto the path of a note each moved away or deleted. The scripted scenario `bothRenameOntoVacatedPath` (`sim/scenarios.ts`) reproduces it under POSIX, macOS and Windows rules: another device edited the synced note `c.md`, moved it to `d.md`, moved the synced note `x.md` onto `c.md` and edited it, while the user deleted `c.md`, moved `x.md` onto it and edited it. The pull of the move to `d.md` moved the user's file aside to a `path-taken` copy, and the merge of the other device's edit of the moved note then reused that logged name for the conflict copy of the user's edit, which was the note's own file: the merge result overwrote it, and the edit was gone. A merge's conflict copy now never reuses a `path-taken` record. The unit regressions are in `plugin/src/core/engine/rename-onto-vacated-both.test.ts`.
