`seed-100051-retention.json`, `seed-100058-retention.json` and `seed-100091-retention.json` are the retention schedules of seeds 100051, 100058 and 100091 of #480 (3000 steps, 3 clients, 2 engines: Windows and macOS rules), as minimized by nightly run 39395203115 to 1505, 2645 and 3012 steps (their recorded `violations` are the nightly's). Retention purged the revision at the macOS engine `e4`'s cursor, so its pull reported `diverged` and it resynced. The resync handed every document the journal knew at another revision to the merge hook, as after a database restore, so a note another device had deleted kept its unchanged file as an edit against the delete, and the next push committed it back (`resurrected-delete`). When the feed skips the cursor's own seq, a resync now applies the heads of documents whose synced revision the server still holds (or purged) as a pull would, and merges only those the user changed (SPEC.md §8). The scripted scenario `purgedCursor` (`sim/scenarios.ts`) drives the same shape directly, and `plugin/src/core/engine/purged-cursor.test.ts` holds the unit regressions.
