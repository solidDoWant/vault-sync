`seed-5-retention.json` is retention seed 5 of #229 minimized in #344 (macOS engine); it needs the `retention` step (#297), which purges the merge base. The user renamed the synced note `ab:c.md` to `Notes/C.md` while another device renamed it to `NOTES`. The local rename wins, and the local version needs a conflict copy in `Notes/`. The merge holds the remote revision deferred while it writes the copy, and it counted that revision's own path `NOTES`, where the merge result does not go, as a file named like the folder `notes/`. So no copy name was free, the merge stayed deferred, and `Notes/C.md` never synced. #352's fix (a file named like a folder of the merge result's path never blocks a conflict copy) fixed this too, so the seed is a regression only. The scripted scenario `localRenameIntoRemoteRenamesFolder` (`sim/scenarios.ts`) covers the same shape under POSIX, macOS and Windows rules, with overlapping edits in place of the purged base.
