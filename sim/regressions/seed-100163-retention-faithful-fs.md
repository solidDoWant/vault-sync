A remote revision of a document goes to the merge path, and the path merge keeps the document's local rename (to `STRASSE.md` or `straße.md`). That path collides under the server's key with another live document's synced path (`Straße.md` or `STRASSE.md`), which on the faithful filesystem is a file of its own. Rule W keeps the other document there (its newest server claim is the path under `K`), so the revision waited as `path-conflict` for good: the engine held a file that was no live document's and missed the document's path on the server. Since #846 the local rename moves on to a conflict-copy name under the document's own id, as a commit refused with `ALREADY_EXISTS` would (PO-4(a) from its side, design §4.5), and the merge result goes there.
